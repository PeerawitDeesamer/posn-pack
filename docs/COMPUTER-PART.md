# พาร์ทวิทยาการคำนวณ — ขอบเขต แนวโจทย์ และวิธีตรวจ

พาร์ทนี้ในข้อสอบจริงคือ "ตอนที่ 2-3" ของปี 68 (ปรนัย 25 + อัตนัย 5)
วัดสองอย่างเท่านั้นตาม `เนื้อหาที่ใช้สอบ.pdf`

1. การโปรแกรมพื้นฐานภาษาไพธอน
2. การคิดเชิงวิเคราะห์และการแก้ปัญหาตามขั้นตอนวิธีที่ให้

## ขอบเขตภาษาไพธอนที่ใช้ได้ (เกินนี้ห้ามเด็ดขาด)

**ใช้ได้**

- กำหนดค่าตัวแปร `=`
- นิพจน์คำนวณ `+ - * / // % **`
- นิพจน์เปรียบเทียบ `== != < <= > >=`
- ตัวเชื่อมตรรกะ `not and or`
- `if` เดี่ยว, `if-else`, `if` ซ้อน `if`
- `while` และการผสม `if` กับ `while`
- `print()`

**ห้ามใช้** (นอกขอบเขต ถึงจะเขียนง่ายกว่าก็ห้าม)

- `def` ฟังก์ชัน / `return` / `lambda`
- `for` และ `range()` — ต้องเขียนเป็น `while` เสมอ
- `list` `dict` `set` `tuple` และการ index `a[i]`
- `import` อะไรก็ตาม
- string method (`.split()` `.upper()`) และ f-string
- `try/except` `break` `continue` — ยกเว้นใส่ **หมายเหตุอธิบายความหมายไว้ในโจทย์**
  (ข้อสอบจริงทำแบบนี้กับ `continue`)

ตัวไหนที่นักเรียนอาจไม่คุ้น (`//` `%` `**` `!=`) ให้ใส่ `\note{}` อธิบายไว้ใต้โจทย์
ข้อสอบจริงอธิบายทุกครั้ง อย่าถือว่ารู้แล้ว

**โจทย์ที่เป็นขั้นตอนวิธีเชิงบรรยาย** (ขั้นตอนที่ 1), 2), 3) …) ไม่ต้องใช้ไวยากรณ์ไพธอน
เขียนเป็นภาษาไทยเป็นขั้น ๆ ได้เลย — ข้อสอบจริงใช้ทั้งสองแบบพอ ๆ กัน

## หัวข้อ 9 กลุ่ม (รหัสที่ใช้กับ `--focus`)

| รหัส | หัวข้อ | รูปแบบโจทย์ที่ออกได้ |
|---|---|---|
| `pyexpr` | นิพจน์ ลำดับดำเนินการ ชนิดข้อมูล | ค่าของนิพจน์, `/` ให้ทศนิยมแต่ `//` ให้จำนวนเต็ม, ลำดับ `**` ก่อน `*` |
| `pycond` | เงื่อนไข if ซ้อน ตรรกะประกอบ | เงื่อนไขไหนสมมูลกัน, ค่า x แบบไหนทำให้เป็น True เสมอ, if ซ้อนสามชั้นเข้าสาขาไหน |
| `pyloop` | while ไล่ค่าตัวแปร | ผลลัพธ์ที่พิมพ์, ค่าตัวแปรเมื่อออกจากลูป, ลูปวนกี่รอบ |
| `pymix` | if+while ผสม | ตัวไม่แปรผัน, ลูปหยุดหรือไม่หยุด, เปลี่ยนค่าเริ่มต้นแล้วผลเปลี่ยนอย่างไร |
| `algotrace` | ทำตามขั้นตอนวิธีที่ให้ | ให้อินพุต หาเอาต์พุต — ข้อสอบจริงออกบ่อยที่สุด |
| `algocount` | นับจำนวนครั้งการทำงาน | ขั้นตอนที่ 3 ถูกทำงานกี่ครั้ง, เปรียบเทียบค่ากี่ครั้ง |
| `algomod` | เปลี่ยนขั้นตอนบางจุด | ถ้าสลับขั้นที่ 2 กับ 3 ผลลัพธ์เปลี่ยนไหม, เปลี่ยน `<` เป็น `<=` แล้วอย่างไร |
| `simulate` | จำลองสถานการณ์ตามกฎ | คิวรับคืนหนังสือ, น้ำมันรั่วระหว่างทาง, แจกลูกอมเป็นรอบ |
| `greedy` | เลือกดีที่สุดทีละขั้น | เปิดสปริงเกอร์อย่างน้อยกี่ตัวให้ครอบคลุม, จับคู่ให้ได้มากที่สุด |

`simulate` และ `greedy` เป็นแนวที่ข้อสอบจริงชอบใช้กับ **ตอนอัตนัย** เพราะคำตอบเป็นจำนวนเต็มพอดี

## กฎเหล็กเฉพาะพาร์ทนี้

1. **โปรแกรมทุกชิ้นในโจทย์ต้องรันจริงใน `verify.py`** ห้ามไล่ด้วยตาแล้วเชื่อ
   ก๊อปโค้ดจากโจทย์มาวางแล้วรัน แล้วเทียบเอาต์พุตกับตัวเลือกที่จะพิมพ์
2. **โค้ดในโจทย์กับโค้ดใน `verify.py` ต้องเป็นข้อความเดียวกันเป๊ะ** วิธีที่กันพลาดได้จริงคือ
   เก็บโค้ดเป็นสตริงตัวเดียวใน `verify.py` แล้ว `exec()` มัน และ `print()` สตริงเดียวกันนั้น
   ออกมาวางในไฟล์ `.tex` — อย่าพิมพ์ซ้ำสองที่
3. **ต้องเช็คว่าลูปหยุดจริง** ก่อน `exec` ใส่ตัวนับรอบ ถ้าเกิน 10⁶ รอบให้ error
   ข้อที่ตั้งใจให้ลูปไม่หยุดต้องพิสูจน์ว่าไม่หยุดด้วยเหตุผล ไม่ใช่ปล่อยให้สคริปต์ค้าง
4. **ตัวลวงต้องมาจากความผิดที่เกิดจริง** เช่น ค่าที่ได้ถ้าออกจากลูปช้าไป 1 รอบ,
   ค่าที่ได้ถ้าสลับลำดับสองบรรทัด, ค่าที่ได้ถ้าใช้ `/` แทน `//` — ห้ามสุ่มตัวเลขมั่ว
5. **ห้ามให้ผลลัพธ์เป็นทศนิยมยาว** ถ้าโจทย์ใช้ `/` ให้ออกแบบเลขให้หารลงตัว
   หรือเปลี่ยนเป็น `//` ตั้งแต่แรก
6. **การจัดรูปโค้ดใน LaTeX** ใช้ `verbatim`-style ที่ฟอนต์ monospace และรักษาย่อหน้า
   ระดับการเยื้อง (indent) คือความหมายของโปรแกรม เยื้องเพี้ยน = โจทย์ผิด ต้องดูจากภาพ PNG ทุกข้อ

## แม่แบบ LaTeX สำหรับบล็อกโค้ด

```latex
\usepackage{fancyvrb}
\newcommand{\code}[1]{\texttt{\small #1}}     % โค้ดสั้นในบรรทัด
\DefineVerbatimEnvironment{pycode}{Verbatim}%
  {fontsize=\small, xleftmargin=2.4em, baselinestretch=0.95, commandchars=\\\{\}}
```

ใช้แบบนี้

```latex
\item โปรแกรมต่อไปนี้แสดงผลลัพธ์ตรงกับข้อใด
\begin{pycode}
x = 2
while x < 20:
    x = x + 5
    if x % 3 == 0:
        x = x - 1
print(x)
\end{pycode}
\chfour{$19$}{$20$}{$23$}{$24$}
```

**ต้องใช้ `Verbatim` ไม่ใช่ `\texttt` ธรรมดา** — ข้อความไทยตั้ง `\XeTeXlinebreaklocale`
ไว้ ทำให้ช่องว่างนำหน้าบรรทัดถูกยุบ การเยื้องของไพธอนจะหายไปทั้งหมด

`\small` เพราะฟอนต์ monospace ที่ขนาดเดียวกับ TH Sarabun New จะดูใหญ่เกินสัดส่วน
ข้อสอบจริงพิมพ์โค้ดเล็กกว่าเนื้อความประมาณ 1 สเต็ป

## โครงร่าง verify.py ของพาร์ทคอม

```python
# โค้ดในโจทย์กับที่รันต้องเป็นสตริงเดียวกัน — พิมพ์ครั้งเดียว ใช้สองที่
Q3 = '''
x = 2
while x < 20:
    x = x + 5
    if x % 3 == 0:
        x = x - 1
print(x)
'''

import io, sys, ast

def run(src, limit=10**6):
    """รันโค้ดโจทย์ พร้อมกันไวยากรณ์นอกขอบเขตและลูปไม่รู้จบ คืนสิ่งที่ print ออกมา"""
    tree = ast.parse(src)
    for node in ast.walk(tree):
        if isinstance(node, (ast.For, ast.FunctionDef, ast.Import,
                             ast.ImportFrom, ast.ListComp, ast.Subscript)):
            raise SystemExit(f'โจทย์ใช้ {type(node).__name__} ซึ่งอยู่นอกขอบเขตข้อสอบ')
    steps = [0]
    def guard(frame, event, arg):
        steps[0] += 1
        if steps[0] > limit:
            raise RuntimeError(f'ลูปไม่หยุดภายใน {limit} ขั้น')
        return guard
    buf, old = io.StringIO(), sys.stdout
    sys.stdout = buf
    sys.settrace(guard)
    try:
        exec(compile(tree, '<q>', 'exec'), {})
    finally:
        sys.settrace(None)
        sys.stdout = old
    return buf.getvalue().strip()

R[3] = run(Q3)
print('ข้อ 3 →', R[3])            # ต้องตรงกับตัวเลือกที่จะพิมพ์ในข้อสอบ
```

เขียน `print('ข้อ N →', R[N])` ให้ครบทุกข้อ แล้ว **ก๊อปค่าจากเอาต์พุตไปวางในตัวเลือก**
ห้ามพิมพ์ตัวเลขจากที่คิดในหัว

สำหรับข้อ `algocount` ให้ใส่ตัวนับลงในโค้ดที่รัน (แต่ไม่ใส่ในโจทย์) แล้ว print ค่าตัวนับออกมา

## จุดที่พลาดบ่อยในพาร์ทนี้

| อาการ | สาเหตุ | ทางแก้ |
|---|---|---|
| การเยื้องของโค้ดหายในหน้า PDF | ใช้ `\texttt` แทน `Verbatim` | ใช้ `pycode` environment |
| เอาต์พุตมี `.0` ต่อท้าย | ใช้ `/` แทน `//` | เปลี่ยนเป็น `//` หรือออกแบบเลขให้ลงตัว |
| ตัวเลือกไม่มีข้อถูก | แก้โค้ดในโจทย์แล้วลืมรันซ้ำ | รัน `verify.py` ใหม่ทุกครั้งที่แตะโค้ด |
| นักเรียนตีความ `while` ผิดเพราะไม่มีวงเล็บ | ลืมใส่ `\note{}` อธิบายตัวดำเนินการ | ใส่หมายเหตุทุกครั้งที่ใช้ `//` `%` `**` `!=` |
| ข้อ `algocount` เถียงได้ว่านับอะไร | โจทย์ไม่ได้ระบุว่านับ "การเปรียบเทียบ" หรือ "รอบ" | เขียนให้ชัดว่านับคำสั่งบรรทัดไหน |
