# ขนาดฟอนต์ — วิธีวัดให้ตรงข้อสอบจริง

**ค่าที่ใช้อยู่: `Scale = 1.112`** ตั้งไว้ใน `assets/preamble-exam.tex` แล้ว
มาจากการวัด ไม่ใช่การกะ **อย่าแก้ด้วยการเดา** ถ้าจะแก้ ต้องวัดใหม่ตามวิธีในไฟล์นี้

## วิธีวัด

```bash
python3 ~/.claude/skills/posn/scripts/measure_font_size.py \
    ~/Documents/POSN.Computer/ไฟล์ข้อสอบ/"ข้อสอบสอวนคอมปี 68.pdf" examN.pdf
# → MEDIAN RATIO (เรา/จริง) = 0.9994    (1.00 = ตรงเป๊ะ)
```

`preflight.py` เรียกสคริปต์นี้ให้อยู่แล้ว และ FAIL ถ้า ratio ห่างจาก 1.00 เกิน 0.01
รันมือเฉพาะตอนที่กำลังหาค่า `Scale` ใหม่

ปรับด้วย: **`Scale` ใหม่ = `Scale` เดิม ÷ ratio**

## หลักการที่ทำให้ตัวเลขนี้เชื่อได้

สคริปต์ใช้ **PyMuPDF** ซึ่งคืนขนาดฟอนต์จริง (em size หน่วย pt) ของทุก span ในหน้า
จึงเทียบได้ตรง ๆ นับเฉพาะ span ที่มีอักษรไทย ถ่วงน้ำหนักด้วยจำนวนตัวอักษร แล้วเอาขนาด
ที่ครองหน้ามากที่สุด (ตัวเนื้อความ) มาหารกัน หัวข้อกับเชิงอรรถขนาดต่างออกไปจึงไม่ถูกนับ

**ใช้ได้เฉพาะเมื่อทั้งสองไฟล์เป็นฟอนต์ตระกูลเดียวกัน (TH Sarabun)**
อย่าเอาไปเทียบตัวเลขหรืออักษรละติน เพราะของเราเป็น Computer Modern คนละ metrics

วิธีเดิมใช้ `pdftotext -bbox` แล้วจับคู่คำไทยคำเดียวกันในสองไฟล์ ซึ่งได้ผลตรงกัน (0.9994
ทั้งคู่) แต่ต้องพึ่ง poppler ที่ลงยากบนเครื่องไม่มี package manager และต้องจับคู่คำเพราะ
`-bbox` คืน *กล่องฟอนต์* (ascent+descent ≈ 1.1 เท่าของ em) ไม่ใช่ขนาดฟอนต์
PyMuPDF อ่านขนาดตรง ๆ ได้เลยจึงไม่ต้องจับคู่

## ความสัมพันธ์กับขนาดสูตรคณิตศาสตร์

ขนาดสูตร (Computer Modern) ผูกกับ **class size** ส่วนขนาดตัวหนังสือไทยผูกกับ **Scale**

- อยากให้ตัวหนังสือไทยเล็กลงอย่างเดียว → ลด `Scale` **อย่าแตะ class size**
- ถ้าลด class size สูตรจะเล็กตามไปด้วย และต้องเพิ่ม `Scale` ชดเชย
  (`Scale` ใหม่ = `Scale` เดิม × 14 / ขนาดใหม่)

นี่คือเหตุผลที่ preamble ใช้ `extarticle` 14pt ไม่ใช่ `article` 12pt

## สิ่งที่รู้แต่ตั้งใจไม่ทำตาม

ข้อสอบจริงเป็นกระดาษ **Letter** (612×792 pt) เพราะทำจาก Word
เราใช้ **A4** เพราะปรินต์ในไทยสะดวกกว่า

ถ้าผู้ใช้ขอ "เหมือนจริงทุกอย่าง" จริง ๆ ค่อยเปลี่ยน `geometry` เป็น `letterpaper`
— แต่ต้องบอกผู้ใช้ก่อนว่าปรินต์ลง A4 แล้วขอบจะไม่พอดี
