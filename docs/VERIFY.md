# verify.py — คำนวณทั้งคำตอบถูกและตัวลวง

ไฟล์นี้คือแม่แบบพาร์ทคณิตศาสตร์ ส่วนพาร์ทคอมที่ต้อง `exec()` โค้ดในโจทย์จริง
ดู [COMPUTER-PART.md](COMPUTER-PART.md)

## หลักการเดียวของไฟล์นี้

`R[n]` คือคำตอบถูก `D[n]` คือตัวลวง — **ทั้งสองอย่างต้องมาจากการรันโค้ด ไม่ใช่จากหัว**

กฎเหล็กข้อ 3 บอกว่าห้ามเดาคำตอบ แต่ตัวลวงก็เป็นตัวเลขที่ต้องพิมพ์ลงข้อสอบเหมือนกัน
และเป็นตัวเลขที่นักเรียนครึ่งห้องจะเลือก ตัวลวงที่แต่งขึ้นลอย ๆ ทำให้เกิดสองปัญหา:
ตัวเลือกที่ไม่มีใครเลือก (ตัดทิ้งได้ทันทีโดยไม่ต้องคิด) และคำอธิบายในเฉลยที่เขียนย้อนหลัง
ว่า "น่าจะมาจากคนที่ลืม..." โดยไม่เคยตรวจว่าจริงไหม

`D[]` แก้ทั้งสองข้อพร้อมกัน: ชื่อ key คือความผิดที่ระบุชื่อได้ ค่าคือผลของความผิดนั้น
เมื่อคำนวณจริง

## โครงเต็ม

```python
#!/usr/bin/env python3
# พิมพ์เขียว: comp-set3 | hard | 10 ข้อ  (ก๊อปตารางจาก exam_blueprint.py มาวางตรงนี้)
import sys
from fractions import Fraction
sys.path.insert(0, str(__import__('pathlib').Path.home() /
                       '.claude/skills/posn/scripts'))
from verify_lib import emit

R, D = {}, {}

# ---- ข้อ 1: เลือกกรรมการ 3 คนจาก 8 คน ----
def C(n, r):
    out = 1
    for i in range(r):
        out = out * (n - i) // (i + 1)
    return out

def P(n, r):
    out = 1
    for i in range(r):
        out *= n - i
    return out

R[1] = C(8, 3)
D[1] = {
    'นับลำดับด้วย (ใช้ P แทน C)': P(8, 3),
    'คูณ n กับ r ตรง ๆ':          8 * 3,
    'หารด้วย r แทน r!':           P(8, 3) // 3,
}

# ---- ข้อ 2: จำนวนเต็ม n < 100 ที่ n เป็นคี่ และ n ≡ 1 (mod 6) ----
R[2] = sum(1 for n in range(1, 100) if n % 2 == 1 and n % 6 == 1)
D[2] = {
    'ลืมเงื่อนไข n เป็นคี่':  sum(1 for n in range(1, 100) if n % 6 == 1),
    'ตกเงื่อนไข n < 100':    sum(1 for n in range(1, 1000)
                                if n % 2 == 1 and n % 6 == 1),
    'นับ n = 0 เข้าไปด้วย':  sum(1 for n in range(0, 100)
                                if n % 2 == 1 and n % 6 == 1) + 1,
}

for n in sorted(R):
    print(f'ข้อ {n} → {R[n]}   ตัวลวง {list(D[n].values())}')

emit(R, D, 'comp', 3)      # ตรวจตัวลวง แล้วเขียน verify_out.json
```

## กฎบังคับ 3 ข้อ

1. **ตัวลวงทุกตัวต้องมาจาก `D[]`** ห้ามแต่งตัวเลขขึ้นเองแล้วพิมพ์ลง `.tex`
   ถ้าคิดความผิดที่ทำให้ได้ตัวเลขนั้นไม่ออก แปลว่าตัวลวงนั้นไม่สมจริง
   **ให้เปลี่ยนตัวลวง ไม่ใช่เปลี่ยนคำอธิบาย**
2. **ห้ามมีตัวลวงตัวไหนเท่ากับคำตอบถูก** — เท่าเมื่อไหร่คือข้อนั้นมีคำตอบถูก 2 ตัว
   `emit()` โยน `VerifyError` ให้เอง และตัวลวงในข้อเดียวกันห้ามซ้ำกันเองด้วย
   ไม่งั้นตัวเลือกจริงเหลือ 3 ตัว
3. **ส่วน "ทำไมตัวเลือกอื่นผิด" ในเฉลย ต้องใช้ key ของ `D[]` ตรง ๆ**
   ห้ามเขียนคำอธิบายใหม่ที่ไม่ตรงกับตัวที่คำนวณ

จาก `D[1]` ข้างบน เฉลยเขียนได้ตรง ๆ แบบนี้ ไม่ต้องคิดคำอธิบายใหม่:

```latex
\textbf{ทำไมตัวเลือกอื่นผิด}~~ ก. $24$ คือคูณ $n$ กับ $r$ ตรง ๆ
ข. $112$ คือหารด้วย $r$ แทน $r!$   ง. $336$ คือคนที่นับลำดับด้วย (ใช้ $P$ แทน $C$)
```

## วิธีตั้งชื่อความผิดให้ใช้ได้จริง

| ใช้ได้ | ใช้ไม่ได้ |
|---|---|
| `ลืมกรณี n เป็นเลขคู่` | `คำนวณผิด` |
| `นับลำดับด้วย (ใช้ P แทน C)` | `เข้าใจสูตรผิด` |
| `ตกเงื่อนไข n < 100` | `อ่านโจทย์ไม่ละเอียด` |
| `ออกจากลูปช้าไป 1 รอบ` | `ไล่ค่าพลาด` |
| `ใช้ / แทน //` | `ตัวเลือกนี้ผิด` |

เกณฑ์: ชื่อความผิดต้อง**แปลงเป็นโค้ดที่รันได้** ถ้าเขียนเป็นโค้ดไม่ได้แปลว่ายังไม่เจาะจงพอ

## ที่เหลือของ verify.py เหมือนเดิม

- brute force ดีกว่าสูตรปิดเสมอ เพราะกันพลาดจากการคิดสูตรผิด
  `R[1] = sum(n for n in range(2,500) if n%6==1 and n%8==1 and n%9==1)` ไม่ใช้ `lcm`
- อสมการให้ sample ค่า $x$ ถี่ ๆ แล้วดูช่วงที่เป็นจริง อย่าแก้ด้วยมืออย่างเดียว
- ลำดับ mod ให้หา period จริงแล้ว print ออกมาเทียบกับที่จะเขียนในเฉลย
- ผลลัพธ์ที่เป็นเศษส่วนใช้ `fractions.Fraction` ไม่ใช้ float
