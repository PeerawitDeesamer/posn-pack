Feynman Mode สำหรับข้อ `$3` ของ `$1` ชุดที่ `$2`

หลักการ: ถ้าอธิบายเรื่องหนึ่งให้คนที่ไม่รู้ฟังไม่ได้ แปลว่ายังไม่เข้าใจ — ต่างจากการอ่านเฉลย
แล้วรู้สึกว่าเข้าใจ ซึ่งหลอกตัวเองได้ง่ายมาก

## ลำดับการทำงาน

**1. ให้ผู้ใช้อ่านเฉลยก่อน**

พิมพ์ว่า "อ่านเฉลยข้อ $3 ให้จบก่อน แล้วพิมพ์ พร้อม" แล้วรอ **ห้ามสรุปเฉลยให้ฟังเอง**
ถ้าคุณเล่าเฉลยให้ฟัง สิ่งที่วัดได้จะกลายเป็นความจำระยะสั้น ไม่ใช่ความเข้าใจ

**2. เรียก subagent `posn-student`**

```
Agent(subagent_type: "posn-student",
      prompt: "ผู้ใช้กำลังจะอธิบายวิธีทำโจทย์ข้อหนึ่งให้ฟัง คุณไม่รู้เรื่องนี้มาก่อนเลย
               เริ่มด้วยการขอให้เขาเล่าว่าโจทย์ข้อนี้ถามอะไร แล้วเขาแก้ยังไง")
```

subagent ตัวนี้ `tools: []` คือปิดเครื่องมือทั้งหมด ไม่ให้มันแอบอ่านไฟล์เฉลยมาช่วยตัวเอง
มันต้องรู้แค่ที่ผู้ใช้พูด ไม่งั้นมันจะแกล้งไม่รู้ได้ไม่เนียนและเผลอเติมคำให้ตลอด
**คุณเองก็ห้ามเปิดไฟล์เฉลยระหว่างการสัมภาษณ์ด้วยเหตุผลเดียวกัน**

ผู้ใช้จบด้วยการพิมพ์ "จบ" แล้ว subagent จะสรุป 3 หัวข้อกลับมา

**3. บันทึกหัวข้อ 2 และ 3**

หัวข้อ 2 (ต้องถามซ้ำเกิน 1 ครั้ง) และ 3 (ตอบไม่ได้เลย) คือรูรั่วจริง หัวข้อ 1 ไม่ต้องบันทึก

```bash
python3 ~/.claude/skills/posn/scripts/exam_result.py feynman $1 $2 --n $3 \
    --gap "<จุดที่ 1>" --gap "<จุดที่ 2>" [--key-suspect]
```

ติด `error_type: knowledge-gap` ให้อัตโนมัติ

**4. ถ้าผู้ใช้อธิบายไม่ได้ทั้งที่อ่านเฉลยแล้ว → ใส่ `--key-suspect` แล้วรายงาน**

บอกตรง ๆ ว่า **เฉลยข้อนั้นอาจไม่ผ่านเกณฑ์ของตัวเอง** (เกณฑ์คือ "นักเรียนที่ทำข้อนั้นไม่ได้เลย
ต้องอ่านเฉลยแล้วทำข้อคล้าย ๆ กันได้เอง") พร้อมบอกว่า**ขั้นไหนที่ผู้ใช้ติด** เพื่อเอาไปแก้
เฉลยชุดถัดไป

นี่คือจุดที่ทำให้ Feynman Mode ไม่ใช่แค่เครื่องมือของผู้ใช้ แต่เป็นเครื่องมือปรับปรุงคุณภาพ
เฉลยของสกิลเอง — เฉลยที่อธิบายกลับไม่ได้คือเฉลยที่เขียนไม่ดีพอ ไม่ใช่ผู้ใช้อ่านไม่ละเอียด

**แยกสองกรณีนี้ให้ออกก่อนสรุป**: ผู้ใช้ติดเพราะเฉลย*ข้าม*ขั้นนั้น (เฉลยผิด → รายงาน) กับ
ผู้ใช้ติดเพราะไม่เคยเรียนเครื่องมือที่เฉลยใช้ (ช่องว่างความรู้ → ไม่ใช่ความผิดของเฉลย)

## เมื่อไหร่ควรใช้

ทุก 3 ชุด สุ่มข้อระดับ L4-L5 มา 2 ข้อ — ไม่ต้องทำทุกข้อ การอธิบายกลับ 1 ข้อกินเวลา
10-15 นาที ถ้าบังคับทำทุกข้อผู้ใช้จะเลิกใช้ ดู `docs/ANSWER-KEY.md` หัวข้อท้ายไฟล์
